Method

From ambiguity to verified state.

The same operating discipline applies to an ERP integration, an AI feature, or an agent delivery graph.

  1. Bind the real system

    Resolve the repository, runtime, requirements, constraints, ownership, and current state before proposing a change.

  2. Freeze the contract

    Translate intent into interfaces, edge cases, acceptance criteria, tests, authorization gates, and rollback.

  3. Build through evidence

    Use systematic diagnosis and RED/GREEN/REFACTOR, then keep model and tool execution inside explicit scope.

  4. Verify independently

    Treat completion summaries as claims until diffs, tests, runtime behavior, and fingerprints agree.

AI Practice

A control plane for multi-LLM engineering.

This is not a collection of chat tools. It is a governed task graph with separated roles, bounded execution, evidence, and memory.

  1. Context: current state and relevant memory
  2. Control: Runs, Tasks, Dispatches, and decision gates
  3. Model: role-based LLM and tool routing
  4. Execution: TDD, diagnostics, and bounded changes
  5. Evidence: independent assessment against exact state
  6. Learning: verified knowledge returns to future context
Context

Project registry, requirements, repository state, and filtered historical evidence.

Control

Orca Runs, Tasks, Dispatches, ask/reply decisions, lifecycle, and task DAGs.

Model

Route architecture, implementation, and review to separate models by role and capability.

Execution

Systematic debugging, RED/GREEN/REFACTOR, browsers, APIs, and domain tools.

Evidence

Frozen criteria, raw command results, runtime probes, diffs, and matching fingerprints.

Learning

Claude-mem evidence becomes durable knowledge only after live verification and guarded curation.

Roles are stable. Models are routed.
